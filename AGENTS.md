# AGENTS.md: контекст для `codex-agent-orchestrator`

Мост передаёт ограниченные задачи из Codex CLI локальным кодовым агентам через stdio MCP.

## Запуск / сборка / проверки

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q src
```

Для локальной проверки протокола запусти `python3 src/codex_agent_bridge.py`; сервер читает по одному сообщению JSON-RPC в строке из стандартного ввода.

## Структура

| Путь | Содержимое |
| --- | --- |
| `src/codex_agent_bridge.py` | MCP-сервер и запуск дочерних CLI. |
| `tests/` | Проверки протокола, сборки команд и валидации. |
| `docs/` | Архитектура и инструкции. |
| `.github/workflows/` | Проверки проекта и контроль house-style. |

## Подводные камни

- `agy --print` принимает задачу как значение флага; передавай её как `--print=<текст>` после режима.
- Рабочая копия Git отделяет обычные изменения, но не является системной песочницей. При реализации OpenCode запускается с `--auto`.
- Рабочая копия создаётся от текущего `HEAD`; незакоммиченные изменения исходного проекта туда не копируются.
- Не публикуй настройки Codex, ключи, журналы, токены и личные данные.

## Стиль и ограничения безопасности

- Комментарии объясняют причину решения, а не пересказывают код.
- Эмодзи запрещены во всех файлах.
- Не добавляй зависимости без объяснения причины.
- Не меняй права доступа и не объединяй ветки автоматически.
- Сохраняй исходную ветку пользователя: реализация всегда идёт в отдельной ветке.
